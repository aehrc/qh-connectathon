Two things on the group: the templateExtract extension pointing at a contained resource, and repeats. The # means 'look in this Questionnaire's contained list'. One repeat makes one Observation; three results typed in give three Observations.

This is an ordinary Observation with holes in it. Fixed parts (status, category) are just written in. The parts that come from answers carry an extension holding a FHIRPath expression. Code comes from the chosen test, subject from the QR, date from the Collected answer. Value and unit are next.

The unit is the fiddly bit: it depends on which test was chosen, so it's a nested iif. Code and unit differ only for ferritin: UCUM code ug/L, display µg/L. That's why the Result field has no unit in the form: the template decides it.

This is the bit that trips people up in FHIR JSON. A primitive like a decimal can't carry an extension itself. So the extension sits on a sibling property with an underscore: value becomes _value. Complex types like Coding can hold the extension directly. After the extract, the extensions are gone and the real values are in place.

Four steps per repeat: copy, evaluate, replace, add to the Bundle. Context matters: expressions run against the repeat, but %resource is the whole QR. That's how we get the subject. An expression that returns nothing just drops that element. That's handy, but it also hides mistakes, so test first.
